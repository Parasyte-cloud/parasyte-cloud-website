# PArAsYtE cloud website audit - 17 September 2026

## Scope

Source-level audit of the uploaded `parasyte-cloud-website` Next.js project, covering UX, responsive navigation, accessibility, product credibility, security headers, SEO, failure states, and the PArAsYtE Browser download journey.

## High-impact issues corrected

1. **Production builds were configured to ignore TypeScript and ESLint failures.**
   - Removed `typescript.ignoreBuildErrors` and `eslint.ignoreDuringBuilds` from `next.config.mjs`.
   - Added `npm run typecheck` and `npm run check` scripts.

2. **Mobile navigation did not actually navigate to a selected section.**
   - `goPage()` only changed internal state while every mobile section remained rendered in one document.
   - Mobile navigation now scrolls to the selected section and an `IntersectionObserver` keeps the active state synchronized while the user scrolls normally.

3. **Desktop footer navigation was ineffective.**
   - It attempted `scrollIntoView()` for sections that are not mounted in the desktop page-turn model.
   - Footer navigation now uses the same page controller as the navbar.

4. **Desktop used only 70% of the viewport.**
   - The fixed desktop shell was `70vh`, leaving a large non-content area.
   - The shell now uses `100dvh` and calculates page height from the real nav/footer heights.

5. **First paint was blank until hydration completed.**
   - Removed the full-page `mounted` rendering gate.
   - The site now renders immediately and enhances responsively after hydration.

6. **The public Scanner looked like a live security scanner while generating random local sample data.**
   - Reframed it as an **Interactive Preview**.
   - Added visible disclosure that no live network scan occurs and results are generated locally for demonstration.
   - Added accessible labels and an `aria-live` log region.

7. **Infrastructure status was hard-coded as “Systems operational”.**
   - Replaced with “Architecture snapshot” because no live health endpoint is wired to the site.

8. **PArAsYtE Browser downloads were buried in a navbar dropdown and mobile platforms had no honest state.**
   - Added a dedicated Browser section.
   - Desktop downloads remain available for macOS, Windows and Linux.
   - Android and iOS are explicitly marked **Coming soon** until real Play Store / App Store / TestFlight destinations exist.
   - Added a mobile-beta email entry point rather than fake download links.

9. **Navigation menus lacked robust interaction semantics.**
   - Added `aria-expanded`, `aria-haspopup`, `aria-current`, Escape-to-close, outside-click handling, and improved mobile menu grouping.

10. **The intro animation replayed on every visit and could delay access.**
    - It now runs once per session and is skipped entirely for `prefers-reduced-motion` users.

## Security and trust improvements

- Added `X-Content-Type-Options: nosniff`.
- Added `X-Frame-Options: DENY` and CSP `frame-ancestors 'none'`.
- Added strict referrer policy and restrictive permissions policy.
- Added HSTS for production HTTPS deployments.
- Added `/.well-known/security.txt` with the security contact.
- Removed public-facing raw hardware fingerprint implementation detail from PArA PIN copy.
- Removed the unsupported “zero metadata leakage” wording and replaced it with narrower, technically defensible mTLS language.
- Removed an unverified 24-hour response-time promise from contact copy.

## SEO and resilience improvements

- Added canonical metadata and clearer product-wide description.
- Added robots metadata, `robots.txt` route and sitemap route.
- Added polished application error and 404 states.
- Removed duplicate Google Fonts import from CSS; font loading remains centralized in the root layout.

## UX / visual improvements

- Full-height desktop composition.
- Dedicated PArAsYtE Browser download panel using the existing liquid-glass design system.
- Cleaner top navigation with Browser and Ecosystem menus instead of five competing CTAs.
- Android/iOS release status visible on desktop and mobile.
- Better responsive breakpoints for crowded navigation.
- Improved footer hierarchy and working navigation.
- Skip-to-content link and stronger keyboard/focus behavior.

## Verification performed in this environment

- All local `@/` imports resolve to real source files.
- 22 TypeScript/TSX files pass TypeScript syntax transpilation.
- `next.config.mjs` passes Node syntax validation.
- `package.json` and `public/manifest.json` parse successfully.

## Follow-up work recommended

1. Verify the three existing GitHub desktop release asset URLs from a normal network before production deployment.
2. Replace Android/iOS “Coming soon” states only after genuine store/TestFlight/APK destinations are available.
3. Plan a controlled upgrade from the current Next.js 14.2.5 / React 18 stack; do not combine that major dependency migration with this UI release.
4. If the Scanner becomes a real public service, implement a backend API with authentication/rate limits, allowlisted scan types, auditable data sources, abuse controls, and clear authorization boundaries before changing the preview label to “live”.
5. Wire infrastructure status to a real health/status endpoint before presenting operational availability claims.
